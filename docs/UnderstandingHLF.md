# Hyperledger Fabric Fundamentals

1. Peers - Maintain the ledger (world state and BC) and execute smart contracts to endorse and validate transactions.

2. Orderers - Package endorsed transactions into chronological blocks.

3. Certificate Authority (CA) - Issue X.509 digital certificates and manage cryptographic identities.

4. Channels - Private, isolated "sub-blockchains" that allow specific subset of network members to transact confidentially.

---

→ core.yaml

Tells a HLF peer node how to behave. Sets up network identity (peer ID, org name, listening ports), TLS/security, how peers gossip with each other, chaincode execution rules, etc.

(Doesn't require a lot of change)

---

→ configtx.yaml - Defines the BC network structure

- Organizations - who's in the network (Orderer, Org1, Org2, Org3) with their MSP paths and permission rules.

- Policies - who can read/write/admin (signature - based rules)

- Orderer - Consensus settings (etc raft means the orderer uses RAFT algorithm)

- Channel - The channel profile "kyctoken channel" that ties org + orderers + policies together.

If you could precisely define the configtx.yaml file and provide the following meta data, the rest files can be auto-generated by AI.

    ORDERER_DOMAIN = example.com
    CHANNEL_NAME = kyctokenchannel
    ORGS = ("org1" "org2" "org3")

---

Ports (7051, 8051, 9051) = where the peer listens for transactions. Chaincode execution happens here. Ledger data is stored and queried here.

- example.com = naming / identification scheme, helps with certificates and container networking.

---

→ What stops a peer from just accepting any transaction without checking it ?

Peers aren't forced to accept. Your chaincode runs validation logic and can reject any transaction. If it throws an error, the peer doesn't endorse.

Orderers then check if enough peers endorsed it.

If yes → Orderer creates a block and adds a transaction

If not → Orderer rejects the transaction.

→ Organizational roles within single organization

- org1 peer - The validator

Runs your chaincode. Approves verification transactions.
maintains the ledger copy.

- org1 client - The user / application

Your backend API submits : "Verify Aadhaar for customer"
Cannot approve, only request

- org1 admin - The boss

Sets up network, deploys chaincode

Supply chain Analogy

Client - store manager submitting "ship package to warehouse"
Peer - warehouse inspector validating
Admin - supply chain director.

→ Docker files

→ docker-compose-ca.yaml - Spins up CA to generate and
manage identities. Does it for (orderers), org1, org2, org3)
Issues digital identities to nodes and users

→ docker-compose-network.yaml - Defines and launches the
core blockchain nodes.

→ docker-compose-couch.yaml - Provides state DB for each peer to
store and query ledger data.
Allows peers to query and update the BC state efficiently
instead of scanning the entire chain.
3 CouchDB instances (couchdb.org1, couchdb.org2, couchdb.org3).

---

→ Scripts

→ network.sh - Orchestrates the entire fabric network
lifecycle.
Checks docker/fabric tools are installed, starts CA servers,
starts couchDB, creates channel, deploys chaincode.

→ ca-functions.sh - Helper functions to generate
cryptographic certificates using fabric CA.
Peers and orderers need cryptographic identities to prove
who they are on the network. These functions create those.

→ deploy-channels.sh - Create the channel and join all nodes.
uses configtxgen to generate the channel genesis.

→ deploy-chaincodes.sh - Deploys the KYC token smart
contract to the channel. It builds TS chaincode.
Packages it into .tar.gz (you have noticed this)
Installs package. Commits chaincode to the channel.

---

→ kyctokenchannel.block (inside channel-artifacts) - Genesis
block file for the channel. Generated by deploy-channel.sh
using configtxgen. configtx.yaml = source code, .block file =
compiled binary.

→ organizations/ - Automatically generated directory.
Stores all cryptographic identities (certificates, key, MSP
folders) for Orderer, 3 peer org, CA server data.

→ kyc-token-cc-1.0.tar.gz - Packaged chaincode file.
Contains the compiled KYC token smart contract
ready for deployment. Generated by deploy-chaincodes.sh.
